# 내 아이디어 — Interactive Virtual Research Lab (AI 논문 인터랙티브 가상 연구실)

## 한 줄 소개
> "논문을 열면 그 논문의 실험실이 화면에 차려진다. AI와 함께 조건을 바꿔가며 직접 실험하면서 논문을 이해하는 인터랙티브 가상 연구실."

논문을 설명해주는 AI가 아니라, **논문을 같이 실험해주는 AI**를 만드는 게 목표다.

## 왜 이 문제인가
지금 AI/CV 논문을 공부하는 방식은:
```text
논문 읽기 → 기존 방법(ViT, SimCLR 등)과 비교해야 함 → 직접 코드 짜거나 남의 자료 찾아보기
```
직접 실험 세팅을 하려면 시간이 오래 걸리고, "진짜 그럴까?"라는 질문이 생겨도 바로 확인해볼 방법이 없다. 시중에 조각 기술(코드 샌드박스, 임베딩 시각화 도구)은 있지만, **"논문 입력 → 실험 자동 구성 → 사용자가 직접 조작 → 결과 비교 → AI와 대화하며 재실험"** 을 한 번에 묶어주는 제품은 아직 없다.

## 핵심 가치 (내가 확정한 3가지 원칙)
1. **핵심은 인터랙션, 시각화가 아니다.** 중심 루프는 `사용자 ↔ AI ↔ 실험`이다. 그래프가 예쁜 것보다 내가 조건을 바꿔가며 직접 실험할 수 있는 게 우선이다.
2. **AI는 실행기가 아니라 연구 파트너다.** 단순히 명령을 실행하거나 논문을 설명하는 게 아니라, **통제 변인을 관리하고, 다음 실험을 제안하고, 가설 검증을 같이 하는 역할**을 해야 한다.
3. **1단계는 "자동화", "인지(perception)"가 아니다.** `논문 → 실험 자동화 → 결과 비교`가 1단계 범위다. 3D 공간에서 실험 장면을 그대로 재현하는 수준의 "인지/시각화 고도화"는 2단계 이후의 폴리싱이다.

## 단계별 로드맵

```text
1단계 (0~6개월)   Computer Vision 논문
                  DINO, SimCLR, MoCo, ViT, DETR, YOLO, SAM 등 5~10개
                       │
                       ▼
2단계 (6~12개월)  NLP/LLM 논문
                  Transformer, LoRA, RAG, MoE, Agent 아키텍처
                       │
                       ▼
3단계 (12개월~)   과학/인문 시뮬레이션
                  화학·물리·생명과학 + 경제학·심리학·사회과학
```

**대표 예시(1단계 기준)**: DINO vs 지도학습 ViT vs SimCLR의 표현(representation) 비교 실험 — 이게 내가 원하는 스코프와 인터랙션 방식을 가장 잘 보여주는 케이스.

## 기술 아키텍처

```text
[논문 입력]
     ↓
[논문 파서] — 논문에서 실험 조건/셋업을 구조화된 스펙으로 추출
     ↓
[실험 명세 생성기] — 자연어 지시("배치 사이즈 바꿔봐")를 실험 스펙의 diff로 변환
     ↓
[컨테이너 기반 실행 엔진] — 실제 코드/모델을 격리된 환경에서 실행
     ↓
[결과 비교 뷰어] — 여러 조건의 결과를 나란히 시각화
     ↓
[AI 튜터] — 통제 변인을 고정해 "공정한 비교"를 보장하고, 다음 실험을 제안
```

### 기술 스택 조사 결과 (Unity 같은 게임 엔진은 필요 없다는 결론)
"인터랙티브"를 구현하는 데 Unity 같은 엔진이 필요한지 조사한 결과, **1단계(임베딩/attention 비교)에는 게임 엔진이 필요 없다.** 필요한 건 두 개의 비-API 레이어다.

1. **실제 코드/실험 실행 백엔드** — 처음부터 Jupyter Kernel Gateway를 직접 만들기보다, 샌드박스 클라우드 실행 서비스를 쓰는 게 현실적:
   - **E2B**: Firecracker microVM 기반, Hugging Face/Perplexity가 실제로 쓰는 샌드박스
   - **Modal**: gVisor 컨테이너 기반, T4~H100/B200까지 GPU 카탈로그가 넓어서 GPU 비중이 커지면 유리
2. **결과 시각화/조작 UI** — 이건 게임 엔진 문제가 아니라 **2D/D3.js·Three.js·WebGL 데이터 시각화 문제**다. 참고할 선례:
   - **TensorBoard Embedding Projector** (Google 오픈소스, WebGL 기반 3D 임베딩 투영 + 회전/줌/검색, 독립 배포 가능)
   - **BertViz** (Attention head/model/neuron를 인터랙티브하게 보는 도구)
   - **TensorFlow Playground**(playground.tensorflow.org) — 순수 TypeScript+D3.js로 만든 "슬라이더 바꾸면 모델이 실시간으로 다시 학습" 인터랙티브 익스플레이너. 게임 엔진 없이 이 느낌을 구현한 가장 가까운 선례.
   - 참고: **ONNX Runtime Web + WebGPU**로 작은 모델을 브라우저에서 직접 돌려 서버 왕복 없이 즉시 반응하는 슬라이더 데모도 가능하지만, 벤치마크상 WebGPU가 WASM보다 최대 6배 느린 경우도 있어 선택적으로만 적용해야 한다.
   - Unity/게임 엔진은 **3D volumetric·VR 몰입형 과학 시각화(우주론 point-cloud, 세포 구조 등)** 에서만 의미가 있음 → 이건 3단계(화학·물리 시뮬레이션 확장)의 후보 기술이고, 1단계 스코프에는 해당 없음.

## 1인 개발 관점의 현실적 스코프 (직접 평가받은 내용)

전체 3단계 비전(모든 도메인 + 6개 기능 + 구독/마켓플레이스 사업 레이어까지)은 **1인 개발로는 불가능**하다는 게 명확한 결론이었다. 대신 아래처럼 스코프를 좁힌 **1단계 MVP는 1인 개발로 6~10주 안에 현실적으로 가능**하다:

```text
- 고정된 비교 1개 (예: DINO vs 지도학습 ViT)
- 고정된 작은 데이터셋
- 사전학습된 체크포인트로 추론만 (학습은 안 함)
- 시각화는 오픈소스 프로젝터 코드를 포크해서 재사용
- 실행은 E2B에 아웃소싱
```
이게 가능한 이유는 핵심 재료(공식 DINO/ViT 체크포인트, HuggingFace transformers/timm의 700개+ 사전학습 모델, E2B/Modal 샌드박스, TensorBoard Projector/BertViz 시각화)가 **이미 다 존재해서 처음부터 만들 필요가 없기 때문**이다.

다만 지원서에 쓴 낙관적 목표(논문 5개, 자연어 실험 편집, 100명 클로즈드 베타, 6개월 이내)는 **8~12개월이 현실적**이다. 자동화가 잘 안 풀리는 4개 병목:
1. 논문마다 공식 repo의 의존성/평가 방식이 달라서 **"자동 베이스라인 선택"이 진짜로 자동화되긴 어렵다** — 매 논문마다 통합 코드를 손으로 짜야 함
2. "공정한 비교"를 위해 어떤 변인을 고정할지는 **소프트웨어 문제가 아니라 ML 판단 문제**
3. 자연어 지시 → 유효한 실험 스펙 diff 변환에서 **엣지케이스 실패가 반복적으로 나올 것**
4. **GPU 비용 가드레일**(쿼터, 캐시 적중률, 타임아웃)을 처음부터 설계해야 함. 안 하면 100명 베타에서 비용이 터진다.

## 사업화 방향 (모두의 창업 지원서에서 제출한 내용)

### 수익 모델 (3단계)
1. **B2C SaaS 구독** — 무료 티어(가벼운 사전학습 체크포인트 추론만), 유료 티어(GPU 시간, 실험 히스토리, 커스텀 논문 업로드). 학생 요금 월 1만~3만원.
2. **기관 라이선스** — 대학원 강의용 좌석당 연간 라이선스, 부트캠프 커리큘럼 납품, 기업 AI팀 온보딩 패키지.
3. **플랫폼 수수료** — 실험 템플릿 마켓 수수료, GPU 대량 구매 후 크레딧으로 재판매, 온프레미스 설치·유지보수.

비용 방어 논리: 사전학습 체크포인트 + 작은 벤치마크 서브셋 + 결과 캐시 공유로, **같은 조건의 실험은 모든 사용자가 재사용** → 사용자가 늘어도 marginal cost가 줄어드는 구조.

### 초기 시장 진입
대학원 논문 세미나부터 시작. 한 랩이 보통 **일주일에 논문 1개씩 소비**하기 때문에 자연스러운 반복 사용처가 된다.

### 마일스톤
```text
1~2개월   프로토타입 + 사용자 인터뷰 20명
3~4개월   논문 5개 지원 + 클로즈드 베타 100명
5~6개월   퍼블릭 베타 + 대학 파일럿 1~2곳
7~12개월  NLP 확장 + 기관 계약 + 시드 투자 라운드
```

### 대외 피칭 문구
> "논문 읽다가 '진짜 그럴까?' 싶었던 적 있나요? 논문을 설명해주는 AI 말고, 논문을 같이 실험해주는 AI를 만듭니다."

## 다음에 해야 할 것 (실행 체크리스트)
1. **DINO vs 지도학습 ViT 비교 1개만** 정하고 범위를 자르기 (다른 논문/기능 욕심내지 않기)
2. HuggingFace/timm에서 두 모델의 **사전학습 체크포인트** 확보, 학습 없이 추론만
3. **E2B 샌드박스** 계정 만들어서 최소 실행 파이프라인 하나 붙여보기
4. **TensorBoard Embedding Projector** 코드를 포크해서 내 데이터로 띄워보기 (시각화는 새로 안 만들기)
5. 이 4개가 붙으면, "AI 튜터"(통제 변인 관리 + 다음 실험 제안) 레이어를 가장 마지막에 얹기
6. GPU 비용 가드레일(쿼터/캐시/타임아웃)은 프로토타입 단계에서부터 설계해두기 — 나중에 넣으면 늦음

## 결론
- 이 아이디어의 본질은 "가상 실험실을 만든다"가 아니라 **"논문을 읽는 순간 그 실험실이 차려지고, AI와 대화하며 조건을 바꿔보는 학습 루프"** 다.
- 1인 개발로 부딛히지 않을 범위는 이미 정해졌다: **DINO vs ViT 하나, 추론만, 기존 오픈소스 시각화 재사용, 실행은 외부 샌드박스에 위임.**
- 진짜 어려운 부분(논문마다 다른 통합 코드, 공정한 비교 판단, GPU 비용 관리)은 소프트웨어로 자동화되지 않는 영역이라는 걸 인지하고, 트래픽이 확인된 후에 co-founder나 계약 ML 엔지니어를 데려오는 게 현실적인 순서다.
