# [누수 방지 End-to-End Pipeline]

## 한 줄 정의
- (교차검증 과정에서 일련의 데이터 학습 중에 생기는 데이터 누수문제를 해결하기 위하여 누수 없는 과정을 자동화하고 고정하는 도구)

## 왜 필요한가 / 어떤 문제를 해결하는가
- 교차 검증 과정 train데이터와 vaild 데이터로 나누는 과정에서 vaild의 데이터를 같이 전처리하거나 스케일링, 모델 학습을 하면 데이터를 미리 보고 배우는 데이터 누수 문제가 생기기 때문에 이를 방지하고 사용
- 물론 파이프라인 없이도 직접 올바르게 나눠서 처리하면 되지만 이 전 과정을 매 fold, 매 하이퍼파라미터마다 정확하게 반복하기엔 실수가 있을 수 있음
- 이를 방지하고자 파이프라인이라는 하나의 구조를 생성하여 fold에서 train에만 전처리 fit하고 그 결과를 vaildation에 적용함

## 핵심 동작 방식
- ① TEST 봉인
   │
   │  "마지막까지 성능을 보지 않는다"
   ↓
② 비교 규칙 고정
   │
   │  CV 방식: 4-Fold
   │  평가지표: AP
   │  탐색 방법: Grid / Random
   │  탐색 예산
   │  후보 선택 규칙
   ↓
③ Pipeline 구성
   │
   │  전처리
   │   ├─ 결측값 처리
   │   ├─ 스케일링
   │   └─ 인코딩
   │
   │  ↓
   │  불균형 처리
   │   └─ RandomOverSampler 등
   │
   │  ↓
   │  모델
   ↓
④ DEV에서 하이퍼파라미터 탐색
   │
   │  여러 하이퍼파라미터 조합
   │       ↓
   │   각 조합마다 Pipeline 실행
   │       ↓
   │     4-Fold CV
   │       ↓
   │   각 Fold의 Train에서
   │   전처리 → sampler → 모델 학습
   │       ↓
   │   Validation에서 AP 계산
   │       ↓
   │   평균 AP + 표준편차
   ↓
⑤ 최종 후보 선택
   │
   │  가장 높은 평균 AP를 기준으로
   │       ↓
   │  허용 범위 내 후보들을 확인
   │       ↓
   │  표준편차
   │  모델 복잡도
   │  트리 수 / 깊이 등
   │  기타 선택 기준
   │       ↓
   │  최종 하이퍼파라미터 확정
   ↓
⑥ DEV 전체로 재학습
   │
   │  선택한 하이퍼파라미터 고정
   │       ↓
   │  DEV 전체를 사용
   │       ↓
   │  Pipeline
   │   ├─ 전처리 학습
   │   ├─ 불균형 처리
   │   └─ 모델 학습
   ↓
⑦ TEST 딱 한 번
   │
   │  이미 완성된 Pipeline으로
   │  TEST 예측
   ↓
⑧ 최종 AP


* 교차검증할 때 해당 조합의 하이퍼파라미터를 Train데이터에 적용하여 여러 과정이 담긴 파이프라인을 실행하고 완성된 모델을 vaild 데이터로 AP 계산하여 하나의 하이퍼파라미터에 대한 각 폴드에 대한 AP값을 평균내어 다른 하이퍼파라미터 평균 AP와 비교, 오차 범위 내의 것들과 다른 기준을 토대로 하이퍼파라미터 확정한뒤, refit으로 전체 재학습한 모델에 다시 같은 파이프라인을 적용 마지막으로 테스트 진행하여 최종 AP 산출

## 찾아본 내용 요약
1. CV 과정에서 매번 train과 vaild을 알아서 "A,B,C"가 train, "d"가 vaild 이런식으로 정해준다 파이프라인은 그걸 전달 받아 train에만 수행한다
2. 파이프라인 없어도 vaild 데이터를 구분하여 train데이터만 사용할 수 있게끔 할 수는 있지만 매번 수많은 하이퍼파라미터와 fold마다 그 과정들을 반복하기엔 실수가 생길 수 있기 때문에 하나의 고정되어 있는 구조를 만들어 데이터 누수 문제를 예방하는 것
3. DEV 데이터로 모여진 데이터를 교차검증 과정에서 폴드의 수만큼 매번 다른 train, vaild를 적용하여 비교 검사 적용
4. stratify=y를 통해 클래스 비율을 유지하는 방법을 교차검증 과정에서도 당연히 사용함
