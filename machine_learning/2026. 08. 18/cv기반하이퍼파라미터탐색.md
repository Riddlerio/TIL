# [CV 기반 하이퍼파라미터 탐색과 공정한 후보 선정]

## 한 줄 정의
- (하이퍼파라미터란 학습할 때 정해지는 값이 아니라 모델이 학습하기 전에 사람이 미리 정해주는 설정값이며 CV(교차검증)을 통해 어떤 하이퍼파라미터를 사용하면 성능이 좋은지 각 평균 AP와 표준편차를 계산하여 가장 높은 성능을 가진 하이퍼파라미터를 탐색)
- (공정한 후보 선정은 가능한 조합을 전부 검사하는 Grid search와 가능한 조합 중에서 일부를 무작위로 뽑아 검사하는 random search 두가지 하이퍼 파라미터 조합 중 어떤 결과를 지향하는지에 따라 후보를 선정)

## 왜 필요한가 / 어떤 문제를 해결하는가
- 하이퍼파라미터의 선정은 모델이 원하는 목표를 달성하기 위해 중요한 것이고 그것의 최적의 성능을 알아내기 위해 각 후보 하이퍼파라미터마다 교차검증을 하는 것
- 실상 공정한 후보를 선정하기 위한 방법 중 정확도와 속도 각 Grid, Random 조합을 선정하여 그것들을 각 폴드에 교차검증하여 성능을 높이기 위함

* 탐색 공간이 크고 모든 조합을 다 보기 어려울 때(하이퍼파라미터가 많을때, 연속적인 값의 범위가 넓을 때), 제한된 횟수 안에서 다양한 조합을 빠르게 탐색하고 싶으면 Random Search

## 핵심 동작 방식
- ① TEST 봉인
   │
   │  "여기는 마지막까지 안 본다"
   ↓
② 비교 규칙 고정
   │
   │  4-Fold / AP / 예산 / 후보 선정 규칙
   ↓
③ DEV에서 Grid / Random Search
   │
   │  여러 하이퍼파라미터 조합
   │        ↓
   │     4-Fold CV
   │        ↓
   │   평균 AP + 표준편차
   ↓
④ 최종 후보 선택
   │
   │  평균 AP
   │  → 허용 범위
   │  → 표준편차
   │  → 트리 수
   │  → 깊이
   ↓
⑤ DEV 전체로 재학습 # refit
   │
   │  선택한 설정 고정
   ↓
⑥ TEST 딱 한 번
   │
   ↓
최종 AP

* 여기서 CV를 통해 좋은 하이퍼 파라미터 설정 값을 DEV(TEST를 제외한 값)에 적용시켜 최종 모델 완성하기 위해 재학습하는 것

## 지금까지 알아본 내용 (있다면)
- 파이프라인은 중요한 기능 즉 데이터 누수를 방지하는 역할을 한다
예를 들어 파이프라인으로 지금까지 한 하이퍼파라미터 검색을 한다고 치면 전처리하고 스케일링하고 모델학습하는 과정을 하나로 묶어서 번거롭지 않게 학습은 학습만 할 수 있게 만든 것으로 알아 봤다


Pipeline = 전처리부터 모델까지의 과정을 하나의 흐름으로 묶고, 특히 CV/하이퍼파라미터 탐색 과정에서 각 Fold의 전처리가 올바르게 이루어지도록 해서 데이터 누수를 방지하는 기능

GridSearchCV
│
├─ 하이퍼파라미터 조합 ①
│    ↓
│   CV
│    ↓
│   Pipeline
│    ├─ 전처리
│    └─ 모델 학습
│
├─ 하이퍼파라미터 조합 ②
│    ↓
│   CV
│    ↓
│   Pipeline
│    ├─ 전처리
│    └─ 모델 학습
│
└─ ...

Pipeline을 쓰면 전처리 → CV → 하이퍼파라미터 탐색 → 모델 학습 과정에서 데이터가 섞이는 실수를 방지할 수 있다.
