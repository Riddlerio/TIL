# 6장. Pydantic 스키마 검증

## 핵심 키워드 10개

1. **스키마**: 요청·응답 데이터에 필요한 필드, 타입, 조건을 정한 데이터 계약
2. **Pydantic**: 외부 JSON을 검증해 Python 객체로 만드는 라이브러리
3. **BaseModel**: Pydantic 모델을 정의할 때 상속하는 기본 클래스
4. **필수 필드**: 기본값이 없어 요청에서 반드시 제공해야 하는 필드
5. **Field**: 길이, 기본값, 설명 같은 필드 제약을 선언하는 도구
6. **default_factory**: 인스턴스마다 새로운 기본값을 만드는 함수
7. **Request model**: 클라이언트가 서버에 보내는 JSON의 모양
8. **Response model**: 서버가 만들어 반환하는 JSON의 모양
9. **ValidationError**: 입력이 스키마 조건을 통과하지 못했을 때의 검증 오류
10. **field_validator**: Field만으로 표현하기 어려운 전처리·검증 규칙을 추가하는 도구

## 핵심 내용 정리

- JSON 문법이 맞아도 서비스의 입력 규칙까지 자동으로 만족하는 것은 아닙니다. 예를 들어 제목 최소 2자, 본문 최소 10자, URL 최대 500자 같은 업무 조건은 스키마에 따로 선언해야 합니다.
- `BaseModel`을 상속한 `DocumentCreate`에 `title: str`, `content: str`, `source_url: str`을 선언하면 모델을 생성하는 시점에 필드 존재 여부와 타입을 검증합니다.
- `Field(min_length=2, max_length=100, description="...")`처럼 선언하면 제한 조건과 API 문서 설명이 한곳에 모입니다. 경계값 바로 아래·경계값·바로 위를 모두 테스트하는 습관이 중요합니다.
- `tags: list[str] = Field(default_factory=list, max_length=5)`는 태그가 생략되면 새 빈 리스트를 만들고, 태그 개수는 5개까지 허용한다는 뜻입니다.
- 요청 모델에는 클라이언트가 정할 수 있는 값만 넣고, 응답 모델에는 서버가 만든 `document_id`, `created_at` 같은 필드를 추가합니다. 이렇게 분리하면 필드의 소유자가 명확합니다.
- 검증 실패 때는 `ValidationError.errors()`의 `loc`에서 어느 필드가 문제인지 찾습니다. FastAPI 요청에서는 보통 `422 Unprocessable Entity` 응답으로 전달됩니다.
- `@field_validator(..., mode="before")`는 Field의 길이 검사 전에 실행됩니다. 문자열의 양끝 공백을 먼저 제거하면 공백만 있는 제목·본문·URL도 정상적으로 거절할 수 있습니다.

## 헷갈리기 쉬운 부분

| 구분 | 정확한 이해 |
| --- | --- |
| 타입 선언 vs 업무 검증 | `title: str`은 문자열 여부만 뜻합니다. 글자 수 같은 조건은 `Field`로 추가해야 합니다. |
| `description` vs 오류 메시지 | `description`은 주로 API 문서 설명입니다. 검증 오류의 위치·종류를 직접 바꾸는 값은 아닙니다. |
| 기본값 없음 vs `None` 기본값 | 기본값이 없으면 필수입니다. `= None` 또는 적절한 기본값을 주면 생략 가능 여부가 달라집니다. |
| `default_factory=list` vs `[]` | 변경 가능한 리스트는 요청마다 독립적으로 만들어야 합니다. `default_factory=list`가 이를 명확히 표현합니다. |
| tags의 `max_length=5` | 태그 글자 수가 아니라 리스트 안 원소의 최대 개수입니다. |
| 요청 모델 vs 응답 모델 | 요청에는 사용자가 보내는 값, 응답에는 서버가 생성하거나 공개해도 되는 값을 포함합니다. |
| validator vs Field | 길이·범위처럼 단순한 규칙은 Field를 우선 사용하고, 공백 제거 같은 변환이 필요할 때 validator를 추가합니다. |

## 실전에 많이 쓰는 부분

- **API 입력 검증**: 회원가입, 주문, 검색, 문서 등록 API에서 누락·타입 오류·길이 초과를 endpoint 진입 전에 차단합니다.
- **자동 문서화**: Field의 설명과 제약조건은 FastAPI의 OpenAPI·Swagger 문서에 반영되어 프런트엔드와의 계약을 명확하게 합니다.
- **서버 전용 필드 보호**: ID, 권한, 생성 시각, 내부 상태는 Request model에서 제외해 사용자가 임의로 보내지 못하게 합니다.
- **데이터 정규화**: validator로 앞뒤 공백 제거, 대소문자 통일, 형식 정리 같은 최소 전처리를 한곳에 모읍니다.
- **정확한 오류 응답**: `loc`를 이용해 어느 입력 칸이 잘못됐는지 클라이언트 UI에 표시할 수 있습니다.
- **테스트 케이스 설계**: 필수값 누락, 타입 오류, 최소·최대 경계값, 빈 문자열, 태그 개수 초과를 테스트에 포함합니다.

## 한 줄 복습
